## 1. The goal

A fix wave should not be the last unreviewed change on a branch, and a fix should not quietly change more than
the finding it closes. Every fix round now ends with the coordinator's three-part delta-read and then a fix-diff
delta review over the fix diff only, under a fix brief that bounds the diff, with one fix wave per review event
and a cause tag on every later finding, so a run's record shows the share of post-fix findings a fix wave
introduced (#1078).

### 5.1 The goal

A red written for a behaviour the suite already exercises extends the test that covers it (a tightened assertion,
a row in its table, or a sibling in its file) instead of a new test that re-creates the setup and re-proves what a
neighbour proves; new test functions and files are for behaviour no test covers. The skill says this where a test
is written (the red, Gate 2, the fix brief) and where it is reviewed (both reuse passes, the consolidation pass, the
size check), and the ledger records each red's step so the share of duplicated fix-wave tests can be re-measured
(#1080).
