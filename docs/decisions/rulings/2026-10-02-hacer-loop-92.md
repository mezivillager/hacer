## R790 — a PR branch that carries a merge commit is re-opened from a clean cherry-pick
Builds on: R785
GitHub refused #667 three times with `This branch can't be rebased`: the ruleset requires linear
history, and a rebase merge cannot replay a merge commit. Rewriting an open PR's branch is Gate 4
(`ha-prompt-it`), and any merge other than merge-on-green needs a per-merge go, so the same two
commits were cherry-picked onto `origin/main` as #668, an ordinary publish under `on-green`.

The finding also means #651's stale-green path cannot complete today: its `update-branch` step uses
GitHub's REST update, which adds a merge commit. #669 owns the fix (the GraphQL update with
`updateMethod: REBASE`).
Cost if wrong: an extra PR number per affected branch; until #669 lands, a stale-green PR is
re-opened by hand the same way.
