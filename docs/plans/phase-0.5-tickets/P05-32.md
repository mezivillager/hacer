# P05-32: Replace skipped flaky `@ui` Playwright suites with RTL integration tests

**Type:** Test-infrastructure follow-up | **Gap:** test rigor / CI health
**Depends:** the non-3D UX test foundation (`<Shell>` boundary + `renderShell()` harness + AGENTS.md §3 Step 4.1 rigor)
**Filed:** 2026-06-20

---

## Why

An audit found **4 of 15 Playwright `@ui` suites are `.skip`-ped**, all citing "flaky behavior causing
test slowdowns" rooted in 3D-scene friction (scene-readiness polling, WebGL init, canvas coordinate
projection). That silently leaves their user scenarios **untested**. Now that the non-3D shell is
testable in jsdom via `renderShell()` (no Canvas), most of that coverage can move to fast, reliable RTL
integration tests; only genuinely 3D-dependent assertions should remain in `@ui`.

## Skipped suites to address

| Suite | Likely coverage | Target layer |
|-------|-----------------|--------------|
| `e2e/specs/**/render-sanity.ui.spec.ts` | app mounts, scene becomes ready | Keep a **minimal** `@ui` smoke (genuinely 3D) — de-flake via `__SCENE_READY__`; move any DOM-shell assertions to `renderShell()` |
| `e2e/specs/**/signal-propagation.ui.spec.ts` | signal values propagate through gates | **`@store`** (engine is store-level) + RTL integration for any panel reflection |
| `e2e/specs/**/simulation-control.ui.spec.ts` | run/pause/step controls drive simulation | **RTL integration** (`renderShell()` + `circuitActions`) + `@store` |
| `e2e/specs/**/wire-persistence.ui.spec.ts` | wires persist across operations | **`@store`** (persistence is store-level); RTL integration if a panel surfaces it |

## Approach (per suite)

1. Read the skipped spec; enumerate the **user scenarios / requirements** it intended to cover.
2. For each scenario, decide the right layer per AGENTS.md §3 Step 4.1: RTL integration (`renderShell()`)
   for DOM-shell behavior, `@store` for store contracts, minimal `@ui` only for true 3D dependence.
3. Write the replacement test(s); delete the skipped spec (or trim it to the minimal 3D smoke).
4. No `.skip` left behind — every scenario lands in a green, reliable test.

## Done when

- No `@ui` suite remains `.skip`-ped for flakiness; each former scenario is covered by a passing RTL
  integration and/or `@store` test (or a de-flaked minimal `@ui` smoke where genuinely 3D).
- `pnpm run test:run` and `pnpm run test:e2e:store` green; the suite count reflects the migrated tests.
