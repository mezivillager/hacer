## 3. Findings

### F1 — high — Shaping is not a stage, so runs end dry and fill with the loop's own work

- **Claim.** `ready` computes what is pickable, but nothing computes when to shape. When product rows
  are empty their slots are skipped, and inbox reviews and harness follow-ups take the run.
- **Evidence.**
  - The 2026-10-21 record §5: the run "closed below its 70% stop because nothing pickable remained".
  - Its 52 merges: 28 harness, 23 foundation, 0 spine; 32 panels (C1).
  - 08:40Z, per the brief: 4 pickable. Then a shaper made five foundation issues `agent-ready` between
    09:13:46Z and 09:14:29Z (M2), and `projects` showed foundation ready 7 by 09:20Z.
  - `docs/harness/README.md` has no shaping trigger (`grep -i shap`: only the "queue up" row, :207).
  - Last cycle's S14 asked for a close-or-shape pass each cycle; unshaped went from 76 to 82.
- **Cost if unfixed.** Every run's tail goes to the process, and a run stops early with budget left:
  6 points, about 3 hours at the last run's rate (*inferred*).
- **Fix.** `ready` and `next` print `shape due: <row>` when fewer than 3 product tasks (foundation,
  core, spine, surfaces) are pickable. The coordinator then shapes the oldest unshaped issue of the
  highest such row before it takes an inbox review, and records a ruling for any it cannot shape. Model
  it on `retro due:` (#880). Effort **S**. Decides: **coordinator**.
- **Strongest case against.** A `risk:2` issue shaped by an agent stays `needs-human`, and foundation
  first means the spine should wait, so the stage would mostly produce owner work. *Answer:* the five
  issues shaped this morning were the kind the coordinator may make `agent-ready` (README:207). The
  stage only has to fire.
