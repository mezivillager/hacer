## Goal

A **Test Lab** panel: pick a Project-1 chip and an *implementation source*, click **Run**, and watch the
official nand2tetris `.tst` execute — output table with red diff-cell highlighting and a pass/fail summary.

## Design highlights (full detail in the design spec)

1. **Pluggable implementation source** (`src/core/testing/implementationSources.ts`) — `resolve(chipName)
   → { chip, registry } | null`. Ships `builtin` and `hdl-from-nand` (compiled from a single NAND);
   user-authored chips (P05-18) and the live canvas (P05-26) plug in later as sources with no panel
   changes. This is the long-term-over-ease choice (AGENTS.md §2 / ADR-0003).
2. **Test execution is a store action** — `circuitActions.runChipTest({ chipName, sourceId })` runs the
   engine and writes `testResult`/`testColumns` to the store; the panel is a thin view. This makes test
   runs **programmatically invokable by an AI agent** (AI-Agent-Parity pillar) and gives the `@store` E2E
   a clean entry point.
3. **Thin panel** (`TestResultsPanel.tsx`) in the `RightActionBar` `'tests'` drawer — chip dropdown (with
   a `✓` on completed chips), source dropdown, Run, summary, output table, step count.
4. **Completion tracking** — `localStorage['hacer-completed-chips']` as `JSON string[]` (the contract
   P05-19's browser will reuse); immediate consumer is the dropdown `✓`.

## Reality note — what's testable today

There is **no fallible target yet**: no user-authored chip (P05-18) and no canvas→chip bridge (P05-26).
So today both sources (builtin, HDL-from-NAND) are *reference* implementations that always pass; the
red-diff path is covered by tests (a deliberately-broken stub source) and lights up automatically once a
fallible source registers. The panel is honest about this via the "implementation source" selector.

## Verifiability

| Layer | Requirement |
|-------|----------------|
| **Vitest** | `implementationSources` resolve correctly; `runChipTest` sets `testResult`/`completedChips`; `TestResultsPanel` renders table, highlights the failing cell (broken stub source), shows summary + `✓`. |
| **Store E2E** | `@store` spec: `runChipTest('Not','builtin')` → assert `testResult.passed`; broken case → assert failure detail. Extend `e2e/types/globals.ts` for the action + `testResult` state. |
| **Manual UI** | Open the Tests drawer → pick `Mux`, source "Built from NAND" → Run → green summary + output table. |
