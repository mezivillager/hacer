## Goals (verifiable)

1. **Engine: pure helper** `generateTruthTable(circuit, { maxInputBits })`
   in `src/core/truthTable/` that:
   - Enumerates every assignment of the circuit's `InputNode`s (clamping
     each input to its `width`).
   - Drives `topologicalEval` once per row.
   - Returns a structured `{ headers: { inputs, outputs }, rows: Array<{ inputs, outputs }> }`.
   - Refuses to compute when the **total input bit width** exceeds
     `maxInputBits` (default 8 → up to 256 rows) and surfaces a friendly
     error instead of OOM-ing on a 16-bit bus.
2. **Store action** `generateTruthTable()` exposes the engine via
   `circuitActions` and writes the result to a new
   `truthTable: TruthTable | null` slice. A second action
   `clearTruthTable()` resets it.
3. **UI: drawer-resident result view.** Clicking the existing
   **Generate Truth Table** Quick Action button (currently stubbed in
   `src/components/ui/RightActionBar.tsx`) generates and renders the
   table inline in the Info drawer, beneath the Quick Actions section.
   Empty-canvas / over-budget cases render a clear empty/error state.
4. **Bit width cap is configurable.** Surface the cap in store state so a
   future "expand to N inputs" UX (or a power-user feature flag) can
   raise it without touching the engine.
5. **`<ComingSoon>` wrapper removed from the Generate Truth Table button**
   once the action is wired. The button becomes a live trigger.

## Out of scope (defer)

- **Per-builtin reference truth tables** sourced from `.cmp` fixtures —
  belongs with [P05-22](./P05-22.md) Test Results, which already consumes
  the .tst/.cmp pipeline. This ticket generates the truth table for the
  **user's current circuit**; the spec-table view is P05-22's job.
- **Hex / decimal / binary toggle on output cells** — P05-13's
  `FormatSelector` already exists for I/O nodes. Reuse it in a follow-up
  polish PR if needed; ship hex-only first.
- **Save / export truth table to CSV or markdown** — viable polish for
  later; not blocking.
- **Multi-bit I/O above the bit budget** — the cap can be raised, but
  full 32-bit support (4 billion rows) is permanently out of scope.

## Verifiability

| Layer | Requirement |
|-------|----------------|
| **Vitest** | (a) Engine: 4-row Nand truth table matches the canonical NAND table; 8-row Mux truth table validates select behavior; over-budget circuit returns the documented error. (b) Store: `generateTruthTable()` populates the slice; `clearTruthTable()` resets it. (c) Component: `<TruthTableView>` renders headers + rows for a sample table; empty state when null; error state when over-budget. |
| **Store E2E** | New `@store` spec under `e2e/specs/ui-shell/`: place And + 2 InputNodes + OutputNode → wire the standard 2→1 AND topology → call `generateTruthTable()` → assert rows. | **Manual UI** | Light + dark theme: empty canvas → button generates an empty-state. Place And + 2 InputNodes → button generates a 4-row table. Place a 16-bit bus chip with no spec narrowing → over-budget error renders. |

## Pitfalls

- **Bit budget defaults.** Sum `width` of every `InputNode` and refuse when
  the sum exceeds the cap. 2^N row count grows fast: 8 bits = 256 rows is
  comfortable; 12 bits = 4096 already strains the DOM; 16 bits is a no-go.
- **No-input circuits.** Some user circuits have only outputs (constants or
  unconnected gates). The engine should still produce a 1-row table for
  those, not crash on `Math.pow(2, 0) === 1`.
- **Disconnected outputs.** Surface as `—` in the cell, not `0`, so users
  can distinguish "this output isn't wired" from "this output evaluates to
  0". Reuse the existing `formatSignalLabel` helper from `signalDisplay.ts`.
- **No `useMemo`.** React Compiler bans manual memoization. Generate the
  table inside the store action; the component just reads the slice.
- **Coordinate with P05-22.** If P05-22 lands first, the truth-table view
  may want to share a `<TabularResults>` primitive with the Test Results
  panel. If P05-31 ships first, design the view as a plain DOM table that
  P05-22 can later abstract.
