## Context

HACER stores all circuit state in Zustand (`src/store/circuitStore.ts`, in-memory). Refreshing the browser destroys everything. Project 1 has 15 chips, each taking 15–60 minutes — users need multi-session persistence.

P05-03 (topological sort) made simulation order deterministic; saving and restoring state is now safe. The serialization format must capture:

- All **gates** with type, position, rotation, **width** (post P05-11)
- All **wires** with endpoints, `WireSegment[]` (with `type` / arc fields — **not** `axis`), `crossesWireIds`, optional `width`, optional `signalId`
- All **input nodes** / **output nodes** with name, position, rotation, value (number bitmask), width
- All **junctions** (`JunctionNode`) with signalId and wireIds

### Current state shape — verify in source before writing code

Read `src/store/types.ts` first. Relevant interfaces at the time of writing:

- `WireEndpoint` = `{ type: 'gate' \| 'input' \| 'output' \| 'junction'; entityId: string; pinId?: string }`
- `Wire` = `{ id, signalId?, from, to, segments, crossesWireIds, width? }`
- `WireSegment` (in `src/utils/wiringScheme/types.ts`) = `{ start, end, type: 'horizontal' \| 'vertical' \| 'entry' \| 'exit' \| 'arc', arcCenter?, arcRadius?, crossedWireId? }`
- `GateInstance` = `{ id, type, position, rotation, inputs: Pin[], outputs: Pin[], selected, width }`
- `InputNode` / `OutputNode` = `{ id, name, position, rotation, value: number, width: number }`
- `JunctionNode` = `{ id, position, signalId, wireIds: string[] }`

UI state (`selectedGateId`, `placementMode`, `wiringFrom`, `lastSimulationError`, `statusMessages`, `propertiesPanelOpen`, etc.) is NOT serialized.

## Goal

After this ticket:

1. `serializeCircuit(state, name)` → `SerializedCircuit` JSON object with `version: 1`
2. `deserializeCircuit(data)` → restored slices (`gates`, `wires`, `inputNodes`, `outputNodes`, `junctions`) ready to merge into the store
3. `saveCircuit(name)` → persists to `localStorage` under a namespaced key
4. `loadCircuit(name)` → clears UI state, replaces circuit slices, ticks simulation once to refresh outputs
5. `listSavedCircuits()` → returns `Array<{ name: string; savedAt: string }>` (sorted newest first)
6. `deleteSavedCircuit(name)` → removes from `localStorage`
7. Auto-save on every meaningful state change (debounced; uses dedicated `__autosave__` key)
8. Export → triggers `Blob` download of `<name>.circuit.json`; Import → reads a `File`, validates, calls load flow
9. `CircuitLibrary` UI panel: list, save (with name input), load, delete, export, import

Toasts via `notify` (`@/lib/notify`) for save/load/error feedback.

## Files to Create

### `src/core/serialization/types.ts`

```typescript
export const CIRCUIT_FORMAT_VERSION = 1 as const

export interface SerializedCircuit {
  version: typeof CIRCUIT_FORMAT_VERSION
  name: string
  savedAt: string // ISO timestamp
  gates: SerializedGate[]
  wires: SerializedWire[]
  inputNodes: SerializedInputNode[]
  outputNodes: SerializedOutputNode[]
  junctions: SerializedJunction[]
}

export interface SerializedGate {
  id: string
  type: string                                // GateType — kept as string for forward compat
  position: { x: number; y: number; z: number }
  rotation: { x: number; y: number; z: number }
  width: number                               // P05-11: required, default 1
}

export interface SerializedWireSegment {
  start: { x: number; y: number; z: number }
  end: { x: number; y: number; z: number }
  type: 'horizontal' | 'vertical' | 'entry' | 'exit' | 'arc'
  arcCenter?: { x: number; y: number; z: number }
  arcRadius?: number
  crossedWireId?: string
}

export interface SerializedWire {
  id: string
  signalId?: string
  from: { type: 'gate' | 'input' | 'output' | 'junction'; entityId: string; pinId?: string }
  to: { type: 'gate' | 'input' | 'output' | 'junction'; entityId: string; pinId?: string }
  segments: SerializedWireSegment[]
  crossesWireIds: string[]
  width?: number
}

export interface SerializedInputNode {
  id: string
  name: string
  position: { x: number; y: number; z: number }
  rotation: { x: number; y: number; z: number }
  value: number                               // bitmask: single-bit uses 0/1
  width: number
}

export interface SerializedOutputNode {
  id: string
  name: string
  position: { x: number; y: number; z: number }
  rotation: { x: number; y: number; z: number }
  value: number
  width: number
}

export interface SerializedJunction {
  id: string
  position: { x: number; y: number; z: number }
  signalId: string
  wireIds: string[]
}
```

### `src/core/serialization/serialize.ts`

Pure: takes a plain `CircuitState` snapshot (NEVER an Immer draft), returns `SerializedCircuit`. Deep-copies positions/rotations/segments to detach from store.

### `src/core/serialization/deserialize.ts`

Pure: takes `SerializedCircuit`, returns `{ gates, wires, inputNodes, outputNodes, junctions }`.

- Throws on unknown `version`.
- Re-creates each gate via the **existing exported `createGateInstance(type, position, width)`** in `src/store/actions/gateActions/gateActions.ts`, then **overwrites** `id`, `rotation`, pin IDs (`${id}-in-${i}`, `${id}-out-0` — same scheme `createGateInstance` already uses), and `width`. This preserves the `entityId`/`pinId` references that wires depend on.
- Wires/nodes/junctions are reconstructed by structural mapping with new objects (no shared refs with the input).

### `src/core/serialization/index.ts`

Barrel: `export * from './types'`, `export { serializeCircuit } from './serialize'`, `export { deserializeCircuit, type DeserializedCircuit } from './deserialize'`.

### `src/core/serialization/serialization.test.ts`

Round-trip tests using `useCircuitStore.getState()` snapshots built via `circuitActions.addGate / addWire / addInputNode / addOutputNode / addJunction`. Cover:

- Empty circuit
- Single gate (single-bit + multi-bit width)
- Gate → gate wire
- Input → gate → output flow (with name + value preserved)
- Junction with multiple wireIds
- Wire segments include `arc` with `arcCenter` / `arcRadius` / `crossedWireId`
- Round-trip equality: deserialized output matches serialized input element-for-element
- `version` validation: deserialize throws for `version: 0` and `version: 2`
- Pin IDs survive round-trip (so wire endpoints still resolve)

## Pitfalls

- **Immer drafts are not serializable.** `serializeCircuit` must receive a plain snapshot from `useCircuitStore.getState()`, NEVER an Immer draft. Never call it from inside `set((state) => …)`.
- **ID stability is mandatory.** Gate IDs determine pin IDs (`${gate.id}-in-${i}` / `${gate.id}-out-0`); wire endpoints reference those pin IDs by string. Deserialization must reuse the **saved gate ID** when rebuilding pin arrays. Regenerating IDs will silently orphan wires.
- **`createGateInstance` already lives in `gateActions.ts`.** Use it (and overwrite `id` / `rotation` / pin IDs to match the saved gate) instead of inventing a new `createPinsForGateType` helper.
- **Gate width is part of the gate.** P05-11 added `GateInstance.width` and `Pin.width`. Persist gate `width` and pass it to `createGateInstance(type, position, width)` on load.
- **`WireSegment.type`, not `axis`.** Real shape is `{ start, end, type: 'horizontal' \| 'vertical' \| 'entry' \| 'exit' \| 'arc', arcCenter?, arcRadius?, crossedWireId? }`. Serialize all those fields verbatim.
- **Clear UI state on load.** Before applying restored slices, null out `selectedGateId`, `selectedWireId`, `selectedNodeId`, `selectedNodeType`, `placementMode`, `nodePlacementMode`, `junctionPlacementMode`, `junctionPreview*`, `wiringFrom`, and `lastSimulationError`. (Don't call `clearCircuit()` — it also nukes `statusMessages`, which we want to keep for user feedback.)
- **Tick simulation after load.** Restored gates carry `value: 0` on their pins; restored `inputNodes` carry the saved value. Call `useCircuitStore.getState().simulationTick()` once after the load so outputs reflect inputs.
- **`InputNode.value` defaults to 1.** `addInputNode` initializes new input nodes to `value: 1` (see `nodeActions.ts`). Deserialization must honor the **saved** value, not re-default it.
- **localStorage size and availability.** Each circuit is ~10–80 KB JSON for Project 1 chips. `localStorage` has a 5–10 MB per-origin limit. Wrap reads/writes in `try/catch` and SSR-guard with `typeof window === 'undefined'` (mirror `src/lib/performanceModeStorage.ts`).
- **Autosave subscription registration.** Register once at module load (like the simulation interval). Don't suspend during load — after a successful `loadCircuit`, the autosave timer will fire and snapshot the loaded state into `__autosave__`. That is the desired behaviour (autosave reflects whatever the user is currently working on).
- **Export/Import**: Export uses `URL.createObjectURL(new Blob([json], { type: 'application/json' }))` and a synthesized anchor click. Import reads a `File` via `text()`, parses JSON, validates `version`, and routes through the same code path as `loadCircuit`.
- **Don't break existing tests.** Reset block in `gateActions.test.ts` is the canonical store reset — many tests `useCircuitStore.setState(...)` directly. Tests in `persistenceActions.test.ts` should `localStorage.clear()` in `beforeEach`. The autosave subscription will fire during unrelated tests; rely on the 2-second debounce + `localStorage.clear()` rather than test-mode gating.
